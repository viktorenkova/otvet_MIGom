## Что уже поддерживает код

Есть две существующие границы:

- `LLM_PROVIDER=qwen`: `QWEN_BASE_URL`, `QWEN_API_KEY` — прямой Qwen через совместимый API.
- `LLM_PROVIDER=litellm`: `LITELLM_PROXY_URL`, `LITELLM_API_KEY` — существующий LiteLLM proxy. Если выбранная модель доступна через него, используется ID, настроенный на этом proxy.

Произвольное имя нового провайдера в настройке само по себе не подключает его. Если у вас доступ другого типа, сначала проверим совместимость с этими границами и необходимый объём адаптации; автоматически заменять выбранную вами модель не будем.

Для эксперимента создан отдельный игнорируемый `.env.llm-experiment`. Ключ и полный endpoint не записываются в отслеживаемые файлы. Совместимость подтверждена реальными успешными вызовами. Ключ был опубликован владельцем в чате с явным разрешением временного использования; после завершения разработок владелец обязан отозвать его и выпустить новый.

## Что разработчик настроит сам

- `LLM_PRIMARY_MODEL` по вашему подтверждённому ID.
- `LLM_INPUT_COST_PER_MILLION_USD` и `LLM_OUTPUT_COST_PER_MILLION_USD` по подтверждённому тарифу. Нулевые цены не позволяют исполнять внешний эксперимент.
- `LLM_DEV_BUDGET_USD` и `LLM_DAILY_BUDGET_USD` в пределах вашего разрешения. Во временной БД эксперимента первый лимит используется как предел суммарных расходов этого запуска; перед вызовами выполняется резервирование бюджета.
- Ветку C только в изолированном эксперименте: `ROUTING_ARCHITECTURE=local`, `LLM_UNDERSTANDING_ENABLED=true`.
- Сохранение `ARCHITECTURE_EXPERIMENT=true`, `LLM_ENABLED=false`, `LLM_ROLLOUT_PERCENTAGE=0`. Эти параметры оставляют пользовательскую LLM-переформулировку выключенной.
- Отключение реальных бизнес-API и отправки обращений в эксперименте.
- Ограничение вызова модели четырьмя секундами; модель выбирает только допустимый scenario ID или недостающий признак для уточнения. При сбое используется локальный результат.

Для существующего полного A/B/C/D-runner ветка C может обрабатывать 270 прямых и 270 HTTP-запросов. Это верхняя оценка числа обращений к выбирающей ветке, а не обещание точной стоимости: часть запросов завершится раньше, при ограничениях или исчерпании бюджета внешний вызов не состоится. Стоимость будет оценена после получения модели и цен; оплачиваемый прогон начинается только в пределах указанного вами лимита.

Результат эксперимента — сравнение локального механизма и LLM на одинаковых кандидатах, ошибки, задержка и расходы. Для допуска LLM требуются прирост E2E минимум 5 п.п., отсутствие роста уверенных ошибок, критических нарушений и превышения бюджета/задержки. Автоматические маркеры не заменяют экспертную оценку смысла. Если критерии не выполнены, LLM не становится основной веткой.

## Ответственность

Владелец проекта подтвердил, что выступает экспертом по правилам и ответственным за новые данные. Это назначение не заполняет автоматически аттестацию независимой итоговой приёмки: условия независимости рецензента проверяются отдельно, когда будет готов новый закрытый корпус. Текущий эксперимент использует существующий development/control-корпус и не называется независимым blind-gate.
