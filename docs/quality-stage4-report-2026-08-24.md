# Отчёт по этапу 4: answer layer

Дата фиксации: 24 августа 2026 года.

## Результат

Этап 4 завершён локально. Для всех 141 активных сценариев построены воспроизводимые answer contracts, связывающие сценарий с required, allowed и forbidden fact IDs. Контракты покрывают 574 атомарных факта и четыре утверждённых типа ответа: direct, clarification, status и contact.

Runtime теперь получает утверждённый шаблон и допустимый набор атомарных фактов по scenario ID. Роль LLM ограничена переформулировкой: post-generation verifier запрещает новые суммы, сроки, проценты, телефоны, email и URL, проверяет лексическую опору и наличие обязательных фактов. При любой ошибке используется детерминированный approved template. В журнал маршрута добавляются использованные fact IDs и причина решения verifier.

## Gate этапа

Свежий локальный E2E-прогон на 160 независимых live-кейсах сохранил quality 94,38%, route hit 96,88%, forbidden content 100% и диалоги 100%. Результат полностью совпал с этапом 3 по качеству; p95 составил 372,38 мс.

Экспертный evaluator рассматривает только 155 кейсов с правильными scenario ID и intent:

- все пять критериев одновременно: 97,42% (151/155), gate не ниже 93%;
- тема: 100%;
- полнота: 98,06%;
- релевантность формулировки: 99,35%;
- понятность: 100%;
- отсутствие лишнего: 100%;
- critical unsupported facts: 0;
- нерелевантные блоки: 0,65% (1/155), gate не выше 2%.

Контрактные, LLM/verifier и JSON-проверки: 17/17 тестов после добавления итогового gate-теста.

## Ограничения

Общий release gate live-корпуса остаётся красным только по ambiguous slice: 80% при цели 90%. Это проблема blind/release-маршрутизации, а не answer layer, и она переходит в этап 5. Измеренная задержка reranker остаётся отдельной обязательной задачей до shadow.

## Вклад в итоговую цель

При правильном маршруте 97,42% ответов одновременно соответствуют теме, полноте, релевантности, понятности и отсутствию лишнего. Answer layer теперь fail-closed и трассируется до атомарных фактов; тем самым достигнут запас выше итоговой цели 8/10 на текущем live-контуре. Этап 5 должен подтвердить этот результат на новом blind-наборе без утечки формулировок.
