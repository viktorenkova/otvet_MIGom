# Этап 2: результат эксперимента выбора сценария через Qwen

Дата: 2026-09-04. Решение: **вариант C не принимается; контрольная маршрутизация A остаётся основной**. Это инженерный отбор на существующем контрольном корпусе, а не разрешение выпуска и не независимый blind-gate.

## Условия

- Один и тот же корпус: 270 обращений и прежний проверенный overlay меток.
- Один Top-10 для A, B и C; знания и шаблоны не менялись.
- C использовал `qwen-plus` через Alibaba Cloud Model Studio Singapore. Endpoint и ключ находятся только в игнорируемом локальном env; отчёт содержит SHA endpoint, но не его значение и не ключ.
- Актуальная стоимость: `$0.40` за 1 млн входных и `$1.20` за 1 млн выходных токенов без thinking для `qwen-plus` в Singapore при запросе до 256K согласно официальному тарифу Alibaba Cloud: <https://www.alibabacloud.com/help/en/model-studio/model-pricing>.
- Общий и дневной лимиты — `$1.00`; внешний выбор ограничен четырьмя секундами. Пользовательская LLM-переформулировка выключена.
- Прямой и HTTP-путь проверялись раздельно. Результаты и manifest сохранены в `reports/architecture-experiment-qwen.json`, покейсные трассы — в `.work/architecture-experiment-qwen-details.json`.

## Результаты полного runtime с предусмотренным fallback

| Вариант | Автоматический E2E | Правильный маршрут | Уверенно неверных | p95 полного ответа |
|---|---:|---:|---:|---:|
| A — контроль | 212/270 (78,52%) | 217/270 | 40 из 236 high | 514,86 мс |
| B — локальный единый scorer | 85/270 (31,48%) | 96/270 | 21 из 97 high | 170,13 мс |
| C — Qwen + локальный fallback | 181/270 (67,04%) | 196/270 | 53 из 234 high | 2 194,64 мс |
| D — эталонный маршрут, только размеченные доступные случаи | 227/239 (94,98%) | 239/239 | 12 из 239 high | 120,04 мс |

C повысил автоматический E2E относительно B на 35,56 п.п., но увеличил число уверенных ошибок с 21 до 53. Относительно рабочего контроля A он потерял 31 правильный полный ответ. Он исправил 24 ошибки A и сломал 55 ответов, которые A обрабатывал правильно. Семь случаев дали разные финальные ответы при прямом и HTTP-повторе.

## Отдельно об успешных ответах провайдера

Для 212 прямых случаев Qwen вернула результат, дошедший до структурированной интерпретации. На одинаковом подмножестве:

| Вариант | Полный успех | Правильный маршрут | Уверенно неверных |
|---|---:|---:|---:|
| A | 159/212 | 162/212 | 39 |
| B | 63/212 | 68/212 | 17 |
| C | 159/212 | 168/212 | 49 |

Таким образом, дополнительные шесть правильных маршрутов C не дали прироста полных ответов относительно A и сопровождались десятью дополнительными уверенными ошибками. Из 208 случаев, где LLM выбрала сценарий, правильный полный ответ получен в 159, а 49 high-confidence решений были неверными. Уточнение выбиралось крайне редко. Это подтверждает наблюдение пилота: текущий селектор недостаточно различает «лучший из предложенных вариантов» и «информации достаточно для уверенного ответа».

## Надёжность и бюджет

- Зарегистрировано 536 внешних вызовов: 423 успешных и 113 неуспешных.
- Учтено 1 124 663 входных и 15 101 выходной токен; исправленная оценочная стоимость `$0.46798640`.
- p95 провайдера — 1 806 мс.
- Ошибки: один timeout чтения, шесть HTTP 403, после которых 106 вызовов были остановлены circuit breaker. В 56 прямых случаях сработал локальный fallback.

Во время запуска runtime ошибочно считал стоимость по более низким ставкам другого регионального раздела (`$0.115`/`$0.287`). Сырой отчёт сохранён в `.work/architecture-experiment-qwen-raw.json`; опубликованный JSON содержит исходные настройки и отдельную корректировку, чтобы история измерения не была скрыта. Исправленная стоимость остаётся ниже разрешённого лимита `$1`, а локальный env обновлён до тарифа Singapore.

Официальный тариф указывает бесплатную квоту 1 млн токенов для Singapore. Совпадение отказов с превышением этого объёма делает исчерпание доступной квоты вероятным объяснением HTTP 403, но код не сохраняет тело ответа 403, поэтому это вывод, а не подтверждённая причина. Повтор оставшихся случаев не нужен для решения о текущем варианте: даже на подмножестве успешных вызовов C не улучшил E2E контроля и увеличил уверенные ошибки.

## Решение по критериям плана

| Критерий | Результат |
|---|---|
| Прирост не менее 5 п.п. относительно B | Пройден по автоматическому proxy |
| Уверенные ошибки не увеличились | **Не пройден: 53 против 21** |
| p95 не более 5 секунд | Пройден: 2,19 секунды |
| Критические нарушения и экспертная семантическая оценка | Не подтверждены; три автоматических forbidden-content нарушения требуют ревью |
| Надёжность провайдера | Не пройдена для полного прогона: 113 отказов с учётом circuit breaker |

Вариант C не допускается к следующему этапу и не включается в runtime. Вариант B ранее также не прошёл сравнение. До следующего отдельного эксперимента сохраняется A.

Следующий эксперимент с LLM имеет смысл только после изменения механизма достаточности: селектор должен отдельно возвращать соответствие кандидата и достаточность информации, а high-confidence разрешается лишь по измеримо откалиброванному правилу. Повтор того же prompt на той же архитектуре не устраняет причину уверенных ошибок.
