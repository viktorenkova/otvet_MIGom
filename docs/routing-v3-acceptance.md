# Routing v3 и независимая приёмка

## Что изменено

Routing v3 заменяет конкуренцию разрозненных точечных правил одним порядком обработки:

1. safety и обязательные неоднозначности;
2. нормализация, исправление доменных опечаток и лёгкая морфология;
3. единый гибридный поиск по символьным n-граммам и словам;
4. Top-K кандидатов;
5. ограниченный semantic reranker по объекту, операции и состоянию;
6. ответ только при достаточной оценке и отрыве от второго кандидата, иначе уточнение.

Так общий термин («адрес», «возврат», «документы») больше не должен побеждать специальный сценарий только из-за приоритета одного старого правила.

## Наборы проверки

- `tests/data/routing_v3_closed_control_270.json` — закрытый регрессионный корпус из 110 запросов живого аудита и 160 запросов независимого аудита. В файле зафиксированы количество и SHA-256 содержимого.
- `tests/data/routing_v3_acceptance_seeds.json` — отдельные смысловые основы, не входящие в закрытые 270.
- `tests/data/routing_v3_independent_acceptance.json` — автоматически получаемые варианты с удалением и перестановкой букв, изменением морфологии и порядка слов.

Контрольные 270 нужны для обнаружения регрессий. Они не являются обучающим словарём, и их отдельные фразы нельзя переносить в routing-правила.

## Запуск

```powershell
python -B -m backend.tools.build_routing_v3_control_set
python -B -m backend.tools.generate_routing_variants
python -B -m backend.tools.evaluate_live_queries `
  --mode local `
  --dataset tests/data/routing_v3_independent_acceptance.json `
  --output reports/routing-v3-independent-acceptance.json `
  --production-gate
```

Локальный режим вызывает настоящий HTTP endpoint `/api/chat/message` через FastAPI TestClient. Remote-режим отправляет те же данные на заданный endpoint.

## Стоп-критерии

Доработка этого этапа прекращается, когда одновременно выполнены заранее принятые пороги:

- HTTP: 100%;
- маршрут (сценарий + intent): не менее 85%;
- полный ответ: не менее 80%;
- опечатки: не менее 80%;
- переставленные буквы: не менее 75%;
- морфология: не менее 85%;
- страховщики и отсутствие ответа: не менее 90%;
- неоднозначные запросы: не менее 90%;
- завершение диалогов: не менее 80%;
- запрещённый контент: 100%;
- уверенно неверных маршрутов: не более двух.

`--production-gate` возвращает ненулевой код, если хотя бы одна метрика не выполнена. Это не позволяет считать этап завершённым по средней цифре, скрывающей провал отдельного критичного класса.

## Артефакты

- `reports/routing-v3-live-query-final.json` — полный независимый аудит 160 запросов и диалогов;
- `reports/routing-v3-independent-acceptance.json` — mutation acceptance;
- `reports/routing-v3-closed-control-270.json` — регрессия закрытых 270;
- `reports/routing-v3-confusion-matrix.json` и `docs/routing-v3-confusion-matrix.md` — автоматически построенная матрица перепутанных сценариев.

## Итог прогона

Независимый аудит 160 запросов: маршрут — **95,62%**, полный ответ — **94,38%**, опечатки — **96,15%**, переставленные буквы — **86,96%**, морфология — **96%**, неоднозначные запросы — **90%**, диалоги — **100%**, запрещённый контент — **100%**, уверенно неверные маршруты — **0**.

Отдельный mutation-набор: **116 из 116** запросов прошли маршрут и проверку полного ответа. Все формальные критерии выполнены, поэтому дальнейшая подгонка этого этапа остановлена.

Закрытые 270 включают исторические запросы, но для первых 110 экспертные метки были восстановлены ретроспективно по тексту и скриншотам. Поэтому этот набор служит регрессией и материалом для экспертной сверки, а формальный стоп-критерий применяется к заранее размеченному независимому набору и отдельно сгенерированным вариантам.
