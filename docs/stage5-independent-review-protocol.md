# Stage 5 blind review protocol

Исторический протокол 500/50. Для архитектурной приёмки по плану 2026-09-04 применять `docs/independent-acceptance-implementation-2026-09-04.md` (500 одиночных + 100 двухходовых диалогов). Старый freeze-manifest не разрешает выпуск текущего кандидата.

Цель — получить новый release-корпус минимум из 500 одиночных запросов и 50 реальных диалогов без утечки формулировок в разработку.

1. Review-pack хранится только в `.work/stage5-blind-review-pack.json` и не коммитится. Разработчик роутера не читает и не редактирует поле `text` после подготовки пакета.
2. Рецензент не должен участвовать в изменении роутера, retrieval, reranker, answer contracts или matching configs. Он заполняет общий `reviewer_attestation` с `router_contributor: false`.
3. Для каждого одиночного запроса и каждого хода диалога рецензент заполняет `expected` (допустимые scenario IDs, intents, resolutions, обязательные и запрещённые маркеры), а также `review.status=approved`, `reviewer_id` и `router_contributor=false`.
4. Нельзя добавлять синтетический диалог вместо реального обращения. В сыром источнике 49 многотуровых разговоров, но после обязательной фильтрации уникальности пригодны 45, поэтому до freeze требуются минимум пять новых обезличенных реальных диалогов.
5. Перед первым прогоном выполняется `python -m backend.tools.freeze_stage5_blind_pack`. Команда завершится ошибкой, если не выполнены 500/50, независимая attestation или разметка хотя бы одной записи.
6. После успешного freeze коммитится только manifest с SHA-256. Пакет остаётся закрытым до фиксации результата первого прогона; затем разрешена диагностика по case ID.
